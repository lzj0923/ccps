# CCPS 領域詞彙

## 租房生命週期

- **出租房源状态**：表示一套房产当前是否对外招租；包括“招租中”和“已下架”，独立于房产资产、交房阶段、租约和日常管理状态。
- **房源下架**：停止一套房产继续招租，并把它移入“下架房源”资料库；房产资产仍保留在房产管理中，业主关系、历史租约、账单、附件、维修和收支资料均不受影响。
- **房源重新上架**：把已下架的出租房源恢复为可招租状态；只有仍有有效出租服务、仍在管理且当前没有有效租约时才允许办理。
  _避免使用_：房产下架、删除房产、停用房产、出售房产

- **房产（Physical Unit）**：可管理、交房和核算的实体单位；它可以整租，也可以拆分为多个出租空间。
- **出租空间（Rental Space）**：租约实际占用的最小范围，可以是整套房产或一个房间。每份租约必须绑定一个出租空间。
- **整套空间（Whole-unit Space）**：每套房产固定存在的出租空间；其租期与该房产所有房间空间互斥。
- **合租（Shared Rental）**：同一房产的不同出租空间，在重叠期间分别绑定不同租约和租客。
- **联名承租（Joint Tenancy）**：多个租客共同属于同一份租约；它不同于合租，不通过建立多份房间租约表达。

- **当前出租周期**：同一套房产本次从出租准备、委托授权、招租签约到入住交接的一轮出租，不包含历史委托、旧租约或日常收租。
- **出租周期编号**：复用出租委托编号和 `rental_mandate_id`，作为同一房产每一轮出租的稳定归档标识，不另建重复编号。
- **出租周期附件**：授权书、OTR、租赁合同和交接报告等本次出租资料；必须能追溯到出租委托，租赁合同还必须关联该委托下的租约。
- **房产通用附件**：长期归属于房产、不会随租客或出租次数改变的资料；与出租周期附件分开展示。
- **入住交接**：租客开始入住时完成的交接资料、清单和报告；完成后当前出租流程即完成。
- **日常运营**：入住后的收租、账单、催缴、维修、预备金和提醒，不参与出租流程完成度。
- **结束租约**：正常租期届满且账单结清、转租或提前退租时结束原租约；结束动作必须保留原租约的审计关系。
- **退租交接报告**：结束租约后记录房屋、物件、钥匙、费用和问题交接的报告；必须关联被结束的原租约，与入住交接报告分开。
- **运营月份**：日常运营的月份筛选范围；账单、杂费和收款只在当前租约的该月份内聚合。
- **房产费用**：房产运营产生的管理费、水电费、维修费或其他费用，是统一的费用事项，不得拆成“房产费用”和“租客账单费用”两个业务功能。系统根据费用原始业务来源自动完成后续入账，用户不需要额外选择或查看费用承担方。
  _避免使用_：租客账单费用、租客费用模块、业主费用模块
- **维修工单**：当前租约下的一次报修处理记录；必须绑定当前 lease_id，不能把旧租约的维修记录混入本次运营。
- **运营月份**：日常运营的月份筛选范围；账单、杂费和收款只在当前租约的该月份内聚合。
- **运营账单明细**：附加在当月租金账单上的管理费、水电费、维修转收费或其他费用；每条明细保留承担方和来源。
- **维修工单**：当前租约下的一次报修处理记录；必须绑定当前 lease_id，不能把旧租约的维修记录混入本次运营。

## 已确认规则

1. 出租主流程到入住交接完成即结束，不等待首期收款。
2. 正常到期、转租、提前退租都必须先结束原租约，再完成退租交接报告。
3. 收租、转租和提前退租产生的历史资料不能把新的当前出租周期标记为已完成。
4. 附件签约默认打开当前出租周期；历史周期只能查看和下载，不能重新生成或发起签署。
5. 同一房产的不同出租周期必须独立归档，当前周期不得混入旧委托、旧租约或旧交接资料。
6. 存在有效租约的房源可以停止招租，但该动作不得结束租约或中断收租、维修、催缴等日常管理；有效租约结束前不得重新上架招租。
7. 房源每次下架及重新上架都必须记录原因、备注、操作人和操作时间，且不得覆盖之前的上下架历史。

## 财务自动化

- **业务建议日期**：业务人员提交收费、收款或支出事项时填写的预期日期，仅用于财务核对，不是正式账务日期。
- **实际收款日期（Receipt Date）**：资金实际到达银行或现金账户的日期，由财务确认；用于会计月度到账核对。
- **财务入账日期（Transaction Date）**：该笔收支正式计入 CCPS 余额、业主账单、预备金及报表的日期，由财务确认；所有关联流水必须采用同一日期。
- **来源单据**：产生财务记录的房款分期、租金账单、押金事项、维修工单、预备金事项或普通收支记录；财务记录必须保留可追溯的来源类型和来源编号。
- **中央财务确认**：所有金额从待确认转为已确认、已付款或已收款的唯一业务动作；来源模块只能提交待确认记录或补充资料。

- **收支备注**：附加在任一资金记录上的补充说明，可记录付款来源、承担情况、用途、沟通说明或其他事项；它不拆分账单、不改变应收应付金额，也不参与账户余额计算。同一房产、同一资金类型可以选择沿用最近一次收支备注。
  _避免使用_：分担备注、付款分配、账单拆分

- **系统财务通知**：由租金逾期、房款到期或预备金余额不足等已确认业务事实自动产生的内置通知；不属于可新增、编辑或删除的普通提醒规则。
- **房款分期提醒阶段**：同一笔未结清分期按到期前 7 天、到期当天、逾期 1 天及以后三个阶段自动通知，每个阶段只发送一次。
- **预备金不足提醒周期**：预备金低于最低标准时立即进入提醒范围；余额未恢复时每满 7 天再次提醒。
- **到账确认**：必须由工作人员根据实际到账凭证完成；自动通知不得自动扣款、自动入账或自动确认收款。
- **系统建议预备金**：系统依据房产租金和业主承担的必要经营支出计算出的建议保障金额，不代表实际账户余额。
- **人工预备金标准**：工作人员根据合同或特殊情况明确设置的最低标准；在切回自动模式前，系统不得覆盖。
- **有效预备金标准**：用于判断余额是否不足的当前标准；人工模式采用人工金额，没有人工设置时采用系统建议金额。

6. 系统财务通知必须保留发送记录、渠道状态和审计记录，但不得出现在可编辑提醒规则清单中。
7. 单笔自动通知失败不得阻塞其他到期事项；已结清、已停用或余额已恢复的事项必须自动退出通知范围。
8. 新建预备金账户默认使用系统建议标准；已有人工标准继续保留，只有工作人员主动切回自动模式后才由系统更新。

## 管理后台权限

- **超级管理员（SUPER_ADMIN）**：系统最高权限账号，可查看并办理全部后台业务、财务和系统管理功能；只有超级管理员可以新增、修改或停用其他超级管理员，且任何管理员都不能停用或删除自己的当前账号。
- **财务管理员（FINANCE）**：负责收款、付款、押金、预备金、财务确认、退回重审及财务报表；可以读取核账所需的业务资料，但不负责建立或修改租约等业务关系。
- **业务管理员（BUSINESS）**：负责建案、业主、房产、出租委托、租客、租约及出租流程；可以建立待确认的收费或开支事项，但不能将其确认为实际到账或实际付款。
- **客服管理员（CUSTOMER_SERVICE）**：负责业主与租客沟通、催缴跟进、签署跟进、资料补充、报修受理及通知记录；可以提交事项和上传资料，但不能修改合同核心金额或完成财务确认。
- **行政管理员（ADMINISTRATION）**：负责后台账号、岗位授权、文件模板、基础配置、操作审计与备份；默认只能查看业务和财务结果，不代替业务或财务岗位办理审批。
- **经办权**：建立、编辑并提交一笔业务事项的权限；经办不等于该事项已经生效或已经到账。
- **确认权**：将待处理事项确认为正式业务或正式资金记录的权限；必须与经办权分开控制并保留操作人、时间和原因。
- **退回权**：把已提交或已确认事项退回上一步重新处理的权限；退回不得删除历史记录。
- **数据范围**：账号可查看和操作的建案、房产或客户集合；岗位权限相同的账号也可以拥有不同的数据范围。

9. 后台权限必须同时控制菜单、页面按钮和后端接口，不能只依靠前端隐藏。
10. 业务管理员建立应收、应付或开支事项，财务管理员负责实际收付款确认；客服管理员可以跟进和补充凭证，不能代替财务确认。
11. 已确认记录的退回必须填写原因并保留完整审计轨迹，不允许用物理删除代替退回。
12. 财务确认中的房产费用必须统一展示和办理；底层入账方向可以不同，但不得向用户呈现为两个独立费用功能，也不得要求用户额外选择费用承担方。
13. 所有收款与支出只能在“财务确认”模块确认；来源模块、业主端及其他后端接口不得直接写入已确认状态。
14. 财务确认必须明确财务入账日期；收款类还必须保留实际收款日期，两者不得因界面简化而合并。
15. 财务确认日期变更必须在同一事务内同步至关联收支、押金和预备金流水；任一链接或副作用失败时整笔确认回滚。
16. 已确认金额、收款日期和入账日期不得在来源模块直接修改或作废；必须先在财务确认模块退回待确认，并保留原因与审计轨迹。
