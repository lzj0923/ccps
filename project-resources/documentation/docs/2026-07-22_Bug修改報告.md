# 2026/07/22 Bug 修改報告

今天主要修正租客租金、財務確認及收支報表的問題：補回延遲新增租約的過去月份、支援按天折算首月租金、改善收支報表格式與資料庫相容性，並完成收款歷史、收據下載、付款憑證及操作按鈕的優化。

## 1. 延遲新增租約後，過去月份租金不見

修改後，系統會由租約開始月份逐月建立租金記錄，不再只顯示當月。

操作：租客與租金 → 新增租約 → 開始日期填較早月份 → 儲存 → 以帳單月份查看。

## 2. 首月租金按當月天數計算

新增租約時可選「按當月天數折算」。例如 7 月 16 日開始，系統會按 7 月實際天數計算，完整月份則收整月租金。

操作：新增／修改租約 → 計租方式選「按當月天數折算」→ 儲存 → 查看本期應收。

## 3. 收支明細及匯出格式

報表已改用客戶指定的中英文欄位，並可按全部、項目、業主或單位匯出；付款名稱改為顯示款項用途，銀行資料及餘額格式也已整理。

操作：報表與導出 → 收入與支出明細 → 選日期及匯出範圍 → 匯出 Excel。

## 4. 租金收款歷史、收據及付款憑證

新增按月份、租客、單位查詢已收租金；確認收款會自動產生收據。「補上憑證」改名為「上傳付款憑證」，下載收據改為瀏覽器直接下載，避免點擊無反應。

操作：財務確認 → 租金 → 歷史記錄 → 使用篩選條件 → 點選交易 → 上傳憑證或下載收據。

## 5. 上方總操作按鈕及外觀

上方「上傳付款憑證／下載收據」必須先點選交易才會啟用，不會默認操作第一筆；列表內按鈕仍直接處理各自交易。四個按鈕的大小、圓角、顏色及懸停效果已統一。

操作：先點列表中的交易 → 確認上方顯示交易編號 → 使用上方按鈕。

## 6. 其他修正

- 修正 MySQL 5.7 不支援特定餘額計算語法造成的 500 錯誤。
- 房產基本資料中的固定支出目前不會自動產生收支記錄；修改金額不會影響已確認支出。

## 上線注意

正式環境需執行一次租金計租方式資料庫更新，並對修正前的租約執行缺少月份補回工具。
