# 按流程阶段筛选已生成文件设计

## 目标

“查看之前生成的文件”只展示当前阶段实际需要的文件，不再把当前房产的全部委托文件和交接报告混在一个弹窗里。

## 已确认的阶段映射

| 当前阶段 | 显示文件 | 不显示 |
| --- | --- | --- |
| 出租准备 | 当前出租的交接报告 | 授权委托书、OTR、租赁合约、账单、收据 |
| 委托与授权 | 当前出租的授权委托书及其签署文件 | 交接报告、OTR、租赁合约、账单、收据 |
| 招租与签约 | 当前出租的 OTR、租赁合约及签署文件 | 授权委托书、交接报告、账单、收据 |
| 入住与收款 | 当前出租的首期账单、收款凭证及入住交接报告 | 授权委托书、OTR |

阶段筛选必须先限定到当前出租委托／租约；历史委托及历史租约的文件不能出现在当前阶段列表中。

## 方案选择

1. 在模板中按阶段写多个过滤条件：改动直观，但文件规则会散落在模板和事件处理中。
2. 在组件中建立一个 `generatedFilesForStage(stage)` 纯计算方法：所有阶段映射集中管理，下载逻辑继续复用现有方法，推荐采用。
3. 新建后端按阶段返回文件接口：边界最清晰，但需要新增 API、权限和数据库筛选，超出本次界面优化范围。

## 实现设计

- `generatedFiles` 继续负责构造可下载文件对象。
- 新增按阶段筛选的纯函数／计算逻辑，根据 `generatedFilesStage` 和当前 `rentalWorkbench.currentMandate/currentLease` 过滤。
- 委托文件按 `mandateId` 绑定当前委托；租约文件按 `leaseId` 绑定当前租约；交接报告按 `mandateId` 或报告内容中的当前委托标识绑定。
- 打开弹窗时传入被点击的阶段，标题保留阶段名称，让用户知道自己查看的是哪一阶段的文件。
- 没有当前阶段文件时显示阶段专属的空状态文案，不显示其他阶段文件作为替代。
- 保留现有下载行为和弹窗样式，不新增第二个历史入口。
