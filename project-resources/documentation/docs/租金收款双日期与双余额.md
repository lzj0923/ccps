# 租金收款双日期与双余额

## 业务口径

- 收款日期：实际收到款项的日期，用于会计月度余额核对。
- 入账日期：租金归属月份在业主账单和前端展示的日期，用于业主结算。
- 业主账单余额：按照入账日期计算。
- 会计余额：按照收款日期计算。

例如，9 月租金在 8 月提前收取：会计余额在 8 月增加，业主账单余额到 9 月才增加，因此该笔预收租金不会被纳入 8 月业主结算。

## 预收租金规则

1. 收款确认时保存收款日期和入账日期。
2. 一笔收款完全覆盖多个租金月份时，为每个已完全覆盖月份生成独立租金记录。
3. 后续月份的入账日期自动使用对应租金月份首日。
4. 未完全覆盖的月份不生成独立月份记录，也不提前计入业主账单余额；但已经实际到账的金额仍按收款日期计入会计余额。金额同时保留为租金预收余额，待完全覆盖后再分配至业主账单。

## 数据字段

- `finance_records.receipt_date`：收款日期。
- `finance_records.transaction_date`：入账日期，保留原字段以兼容既有查询和接口。
- `rent_payments.allocated_amount`：本条租金记录实际分配至对应月份的金额，避免多月收款或部分预收被重复统计。

历史数据迁移脚本：`database/migrate_rent_receipt_posting_dates.sql`。应用启动时也会检查并补齐字段，历史数据的收款日期默认回填为原入账日期。

## 页面与核对

- 确认租金收款、批量确认和租金收款维护均支持两个日期。
- 管理端与业主端备用金页面同时展示“业主账单余额”和“会计余额”。
- 月度备用金核对中的“CCPS 系统总余额”使用业主账单余额，即按入账日期计算；会计余额仍按实际收款日期展示，供其他会计场景参考。
