# 租金批量确认误入单笔弹窗 - 修复报告

## BUG描述
- 页面/功能：财务确认 - 租金。
- 操作步骤：勾选多笔租金账单后，点击列表右上角的确认按钮。
- 期望结果：展示批量账单摘要并一次确认全部记录。
- 实际结果：打开单笔“确认租金收款”表单，仍需逐笔处理。

## 复现步骤
1. 打开财务确认的租金页。
2. 勾选两笔待收租金账单。
3. 点击列表右上角确认按钮，页面调用 `openConfirm` 并打开单笔弹窗。

## 根因分析
- 页面同时存在单笔确认按钮和批量确认入口。
- 列表主按钮始终绑定 `openConfirm`，不会根据已勾选记录进入批量流程，造成入口语义冲突。

## 修复方案
- 将租金列表主按钮统一改为“一键确认当前列表/已选记录”。
- 主按钮直接调用 `openBatchConfirm`；单笔确认仅保留在账单详情中。
- 未勾选时自动带入当前页全部待确认账单，勾选后仅处理选中账单。

## 单元测试
- 测试文件：`frontend/tests/admin-finance-batch-confirm.test.mjs`
- 验证列表主按钮绑定批量方法，不再绑定单笔方法。

## 手动验证步骤
1. 打开财务确认 - 租金。
2. 不勾选记录，点击“一键确认当前列表”，确认弹窗展示当前页全部待收账单。
3. 勾选部分记录后再次进入，确认弹窗仅展示选中记录。
4. 在账单详情中仍可执行单笔确认。

## 影响范围
- 仅调整租金确认入口和批量弹窗触发方式，不修改后端入账规则。
