# 预备金充值未进入财务确认 - 修复报告

## BUG 描述

- 管理端预备金页面新增充值后，记录直接确认并更新余额，没有进入财务确认流程。
- “待确认充值”汇总卡只显示数量和金额，无法跳转到财务确认模块。

## 复现步骤

1. 在管理端“预备金”页面点击“新增充值”并提交。
2. 后端创建的财务记录状态为 `paid + confirmed`，同时立即建立预备金流水并更新账户余额。
3. 财务确认模块的预备金列表只读取 `reserve_topup` 待确认记录，因此本次充值不会出现在待确认列表。
4. “待确认充值”汇总指标没有配置操作事件，也无法从指标进入财务模块。
5. 增加回归测试后，数据库状态、提前更新余额和缺少跳转动作均在修复前失败，稳定复现问题。

## 根因分析

- 管理员充值沿用了“直接确认入账”的旧设计，在创建阶段跳过了财务审核状态机。
- 汇总指标没有配置跳转事件，预备金页面与财务确认页面之间缺少快捷入口。

## 修复方案

- 管理员充值创建为 `paid + pending + not_synced`，保留付款人、付款日期、付款方式、银行参考号及备注供财务核对。
- 创建阶段不再新增预备金流水、不更新余额，也不发送“已充值”通知。
- 财务确认通过后，继续复用 `ReserveTopupService` 的原子入账流程：建立预备金流水、更新余额、更新确认状态并发送通知。
- “待确认充值”汇总卡增加“前往财务确认”，点击后进入财务确认模块的预备金待确认页面。
- 更新充值弹窗和操作结果文案，明确“提交后待财务确认”。

## 测试结果

- 前端预备金定向回归测试：10 项全部通过。
- 后端充值创建、SQL 状态和财务确认测试：9 项全部通过。
- 前端生产构建通过。

## 手动验证步骤

1. 进入“预备金”，新增一笔充值并提交。
2. 确认页面余额不会立即增加，“待确认充值”数量和金额增加。
3. 点击汇总卡“前往财务确认”，确认进入财务确认模块的预备金待确认列表。
4. 退回充值，确认余额保持不变；重新提交后再确认。
5. 财务确认通过后，确认预备金流水生成、余额增加，记录转入已确认历史。

## 影响范围

- 直接影响：管理员新增预备金充值、预备金待确认汇总卡、财务预备金确认流程。
- 不影响：业主上传充值凭证流程、预备金返还、批量返还和扣款规则。
