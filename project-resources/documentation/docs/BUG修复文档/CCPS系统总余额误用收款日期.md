# CCPS 系统总余额误用收款日期 - 修复报告

## BUG 描述

- “月度备用金余额核对”弹窗中的 CCPS 系统总余额按收款日期汇总。
- 业务要求是在收款日期和入账日期两个口径中使用入账日期。

## 复现步骤

1. 建立一笔收款日期与入账日期不同的已确认租金记录。
2. 打开管理端“预备金”的“月度余额核对”。
3. 弹窗取各账户的 `accountingBalance`，该字段按 `receipt_date` 计算。
4. 保存核对结果时，后端同样使用优先读取 `receipt_date` 的汇总 SQL。
5. 前后端回归测试在修复前均失败，问题可稳定复现。

## 根因分析

- 核对弹窗误用了“会计余额（按收款日期）”，没有使用系统的“业主账单余额（按入账日期）”。
- 保存接口调用的方法与 SQL 也沿用了按收款日期的口径，导致页面显示值和落库值都不符合要求。

## 修复方案

- 弹窗的 CCPS 系统总余额改为汇总各账户 `currentBalance`。
- 文案明确改为“CCPS 系统总余额（按入账日期）”。
- 后端新增明确命名的 `findPostedTotalBalance` 汇总方法，使用 `finance_records.transaction_date` 和 `rent_payments.allocated_amount`。
- 保存核对结果统一调用按入账日期的汇总方法。

## 测试结果

- 前端日期口径定向测试：5 项全部通过。
- 后端预备金 SQL 与服务定向测试：7 项全部通过。
- 前端生产构建通过。

## 手动验证步骤

1. 建立收款日期与入账日期不同的已确认租金。
2. 打开“预备金”并进入“月度余额核对”。
3. 确认字段显示“CCPS 系统总余额（按入账日期）”。
4. 确认金额与预备金账户列表中的业主账单余额合计一致。
5. 保存核对结果后，确认历史记录中的系统余额与弹窗显示值一致。

## 影响范围

- 直接影响：管理端月度备用金余额核对的显示、差异计算及保存值。
- 不影响：列表中的会计余额（按收款日期）、租金收款与入账日期本身、业主结算逻辑。
