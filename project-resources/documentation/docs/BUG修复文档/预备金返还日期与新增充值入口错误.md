# 预备金返还日期与新增充值入口错误 - 修复报告

## BUG 描述

- 单笔“预备金返还”和“批量返还”界面无法选择返还日期，后端统一使用当天日期。
- 顶部“新增充值”按钮实际打开“设定预备金”弹窗，没有进入充值表单。

## 复现步骤

1. 打开管理端“预备金”页面，进入单笔返还弹窗，表单中没有日期控件。
2. 勾选多个账户并打开“批量返还”，批量设置区同样没有日期控件。
3. 检查两类请求，提交参数均不包含 `paymentDate`；服务层单笔使用 `LocalDate.now()`，批量也从当天开始排程。
4. 点击顶部“新增充值”，工具栏主操作递增 `adminReserveSettingsNonce`，因此打开预备金设置弹窗。
5. 增加回归测试后，修复前两个新增用例均失败，稳定复现问题。

## 根因分析

- 返还日期没有贯通表单状态、API 请求 DTO 和服务层，后端只能自行取当天日期。
- 工具栏“新增充值”的显示文案与事件信号不一致：文案是充值，事件却绑定到设置。

## 修复方案

- 单笔返还新增必填付款日期，默认当天，并随请求提交。
- 批量返还新增必填首笔返还日期，默认当天；拆分转账从所选日期开始，后续分期逐日顺延。
- 后端单笔和批量返还 DTO 新增必填 `paymentDate`，服务层使用请求日期写入财务及现金流记录。
- 将顶部“新增充值”主操作改为触发 `adminReserveDirectTopupNonce`，打开正确的充值表单。

## 单元测试

- 前端定向测试：`frontend/tests/admin-reserve-refund-toolbar.test.mjs`，9 项全部通过。
- 后端定向测试：`AdminReserveManagementServiceTest`，5 项全部通过。
- 后端验证了单笔所选日期入库，以及批量首笔日期与后续逐日顺延日期。
- 前端生产构建通过。
- 前端全量测试共 300 项，271 项通过；29 项为本次修改范围外的既有失败，定向回归用例均通过。

## 手动验证步骤

1. 进入管理端“预备金”，点击顶部“新增充值”，确认打开充值表单而非预备金设置。
2. 打开单笔“预备金返还”，确认可选择日期；提交后检查返还财务记录日期与所选日期一致。
3. 勾选多个账户并打开“批量返还”，确认可选择首笔返还日期。
4. 对超过银行每日额度的返还提交批量安排，确认第一笔使用所选日期，后续记录按天顺延。

## 影响范围

- 直接影响：管理端预备金顶部充值入口、单笔返还、批量返还及对应后端请求。
- 不改变：返还金额、付款方式、备注、银行每日额度拆分和海外手续费规则。
