# 续约押金增加无法确认收款 - 修复报告

## BUG描述

- 页面/功能：租客与租金 - 办理续约、押金管理、财务确认。
- 操作步骤：原押金 RM 20,000.00，续约时把新押金改为 RM 25,000.00 并提交。
- 期望结果：系统生成 RM 5,000.00 押金补收记录，可在押金管理和财务确认中确认收款。
- 实际结果：租约押金总额变为 RM 25,000.00，但没有 RM 5,000.00 的待确认记录。

## 复现步骤

1. 建立押金 RM 20,000.00 的有效租约并确认原押金收款。
2. 为同一租约办理续约，把押金改为 RM 25,000.00。
3. 提交续约并进入押金管理或财务确认。
4. 看不到新增 RM 5,000.00 的待确认押金记录。

## 根因分析

- 表象：续约后只显示新的押金总额，没有补收入口。
- 服务根因：续约流程仅更新 `leases.deposit_amount` 和续约期资料，没有为增加的押金差额建立 `security_deposit` 财务记录。
- 数据库根因：`security_deposit_entries.lease_id` 原为唯一索引，一个租约只能保存一笔押金账单，无法支持续约补收。
- 查询根因：押金账户查询直接关联全部押金账单，多笔账单会造成同一租约重复显示。

## 修复方案

- 续约成功时计算 `新押金 - 原押金`，仅在结果大于零时建立差额押金财务记录、押金条目和现金流。
- 原押金 RM 20,000.00、新押金 RM 25,000.00 时，只生成 RM 5,000.00 待确认记录，不改写原收款。
- 将租约唯一索引改为普通索引，允许同一租约保存原押金及多次续约补收。
- 迁移脚本会检查已完成续约的历史租约，并按“当前应收押金 - 已建立的有效押金账单”补建遗漏的差额待确认记录。
- 押金账户优先展示最新待确认账单，避免多笔记录造成重复行。
- 续约押金字段增加说明文字，明确金额增加、不变和降低时的处理规则。

- 测试文件：`backend/src/test/java/com/ccps/backend/service/AdminTenancyServiceTest.java`
- 测试用例：`renewalCreatesPendingFinanceRecordOnlyForTheIncreasedDepositAmount`
- 复现结果：修复前失败，确认没有调用押金财务建账。
- 修复结果：通过；同时验证押金不变时不会生成重复收款。
- 前端测试：`frontend/tests/admin-renewal-deposit-increase.test.mjs`，验证说明文字完整显示。

## 手动验证步骤

1. 先执行 `database/migrate_renewal_deposit_increase.sql`。
2. 打开“租客与租金”，选择原押金 RM 20,000.00 的租约并办理续约。
3. 将续约押金填写为 RM 25,000.00，确认字段下方显示差额收款说明。
4. 提交续约后进入“押金管理”，确认该租约出现 RM 5,000.00 待确认账单。
5. 进入“财务确认 - 租客押金”确认该笔收款。
6. 返回押金管理，确认押金累计余额为 RM 25,000.00。

## 影响范围

- 直接影响：续约押金增加、押金管理、财务确认。
- 不受影响：原押金收款、租金收款、押金不变的续约。
- 回归测试结果：后端租约服务测试、前端专项测试和生产构建均通过。
