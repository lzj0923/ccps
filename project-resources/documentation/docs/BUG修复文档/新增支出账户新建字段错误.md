# 新增支出账户新建字段错误 - 修复报告

## BUG描述

- 页面/功能：管理端“收支与维修”中的“新增支出”。
- 操作步骤：选择单位，进入关联付款资料，选择业主或管理层，再选择新建账户。
- 期望结果：银行信息与费用账户号码为两个独立区块；银行账户只选择一次“已有账户／新建账户”，费用账户可独立选择或新建，两类资料分别关联并回写房产详情。
- 实际结果：付款方、费用账户、银行和支付账户曾被拆成多个“自己输入”；调整后费用账户又与银行账户混在同一区块，层级不清楚。

## 复现步骤

1. 打开管理端“收支与维修”。
2. 点击“新增支出”并选择单位。
3. 在关联付款资料中选择“业主”。
4. 可看到付款方、费用账户、银行、支付账户分别出现“自己输入”，选择后显示简化字段。

## 根因分析

- 表象：同一账户资料需要多次选择“自己输入”，新建字段与房产详情不一致。
- 根因：前端把完整银行账户资料错误拆成多个独立可新增字段，并把费用账户选择放进银行账户区块，未体现两类资料彼此独立。
- 定位过程：对照问题截图、`AdminMaintenanceWorkspace.vue` 的关联付款资料区，以及房产详情中的业主银行账户和管理层账户字段确认差异。

## 修复方案

- 修改文件：`frontend/src/components/AdminMaintenanceWorkspace.vue`。
- 表单拆成“银行信息”和“费用账户号码”两个独立区块，费用账户不再依赖先选择银行账户才显示。
- 改为“付款方类型 → 所属账户（已有账户／新建账户）”两级选择。
- 已有账户整组带出付款方、银行和支付账户。
- 费用账户号码可选择房产已有账户，或选择“新建费用账户”后填写账户类型和号码。
- 新建费用账户保存时合并回写房产基本资料的 `paymentAccountNumbers`，之后可直接选择。
- “新增维修／编辑维修”同步采用相同的银行信息与费用账户分区、已有账户选择、新建账户校验和房产资料回写规则。
- 银行账户切换不再清空已独立选择的费用账户。
- 新建业主账户使用：银行名称、收款人姓名、银行账号、银行／分行代码、银行地址、SWIFT、单日转账额度、海外银行、海外手续费、备注。
- 新建管理层账户使用：管理层名称、费用用途、银行名称、银行账号、收款户名、分行／SWIFT、备注。
- 新建账户成功提交支出前，仍按原规则回写房产详情并去重。

## 单元测试

- 测试文件：`frontend/tests/admin-maintenance-payment-profile.test.mjs`。
- 测试用例：银行信息与费用账户分区；单一银行账户选择模型；业主和管理层分别使用房产详情字段集；银行及费用账户回写；单位关联 ID。
- 测试结果：相关回归测试 7/7 通过，前端生产构建通过。

## 手动验证步骤

1. 打开“收支与维修 → 新增支出”，选择一个单位。
2. 选择“业主”，确认所属账户只列出现有业主银行账户和“新建账户”。
3. 选择现有账户，确认付款方、银行、支付账号整组带出。
4. 选择“新建账户”，确认显示完整业主银行账户字段。
5. 改选“管理层”并选择“新建账户”，确认显示管理层名称、费用用途、银行账号等管理层字段。
6. 在独立的“费用账户号码”区块选择已有费用账户，确认不受银行账户选择影响。
7. 选择“新建费用账户”，填写账户类型和号码并保存。
8. 保存后进入房产详情，确认新银行账户与新费用账户均已回写且没有重复记录。

## 影响范围

- 直接影响：新增及编辑支出、维修工单的关联付款资料选择和账户回写。
- 间接影响：房产详情中的业主银行账户、管理层银行账户。
- 回归测试结果：相关测试 6/6 通过，前端生产构建通过。
