# 收支与维修支付报告资料不完整 - 修复报告

## 问题说明

- 页面：管理端“收支与维修”。
- 原导出曾直接输出列表资料，随后又扩展成过多的网银明细列，与财务提供的简洁付款报告样式不一致。
- 目标报告只保留指定字段，并在数据区下方提供行政和财务签字栏。

## 修复内容

- “支出”和“维修”分别导出为 `支出支付报告.xlsx`、`维修支付报告.xlsx`。
- 导出当前筛选后的真实记录，只保留 14 列：日期、行政区、房产／单位、业主、租客、收支类别、收支说明、金额、支付方式、付款方、费用账户号码、支付账户号码、Jompay、Ref No.。
- Jompay 没有资料来源时留空；Ref No. 使用支出交易号或维修工单号。
- 数据区下方加入四个签字位：行政部门、行政主管、财务部门、财务主管。
- 表头冻结并设置适合的列宽；金额保持数值并使用两位小数格式。
- 导出前按单位关联房产、业主、当前有效租客和付款账户资料。
- 新增或编辑支出时，把选中的费用账户类型和号码写入支付凭证。
- 新增或编辑维修时，把付款方、银行账号和费用账户保存为工单付款快照；维修完成生成财务记录时再同步到支付凭证。
- 编辑既有记录时回填原费用账户，避免重新选择后误换账户。

## 数据库变更

- `payment_receipts` 新增 `fee_account_type`、`fee_account_no`。
- `maintenance_work_orders` 新增 `payer_name`、`bank_name`、`payment_account_no`、`fee_account_type`、`fee_account_no`。
- 增量迁移：`database/migrate_payment_report_links.sql`。
- 新建数据库定义和最新部署 SQL 已同步，部署脚本已加入该迁移。

## 手动验收

1. 新增一笔支出，选择已有银行账户和已有费用账户，导出“支出支付报告”。
2. 确认表头严格为 14 个指定字段，房产／单位、业主、租客、费用账户和支付账户资料正确。
3. 新增维修并选择付款资料，完成维修后导出“维修支付报告”。
4. 确认数据下方依次存在行政部门、行政主管、财务部门、财务主管签字区。
5. 新建银行或费用账户后，确认资料回写房产详情，重新进入表单可以直接选择。
