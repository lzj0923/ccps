# 新租房流程建案与业主校验

## 问题现象

- 重复的建案编码直到第三步提交房产时才提示，导致前两步资料白填。
- 新建业主使用已存在的手机号时，只显示通用“操作失败”，无法判断失败原因。

## 根因

- 建案编码只在最终创建建案时由后端检查，第一步没有可用性接口与前端校验。
- 业主手机号同时作为业主端登录账号，账号必须唯一；后端返回英文冲突信息后，被前端通用错误处理隐藏。
- 旧逻辑还把业主邮箱作为唯一条件，业务资料与登录账号规则混在一起。

## 修复内容

- 新增建案编码可用性接口，输入和离开输入框时即时校验，点击“下一步”前再次确认。
- 建案编码重复时停留在第一步，并提示选择已有建案或更换编码。
- 保留手机号作为登录账号且必须唯一；重复时明确提示更换手机号或选择已有业主。
- 业主邮箱不再作为业主资料唯一条件；邮箱已用于其他登录账号时，不阻断业主资料创建。
- 身份证件号码继续保持唯一并提供明确提示。
