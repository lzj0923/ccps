# 租客账单费用绕过财务确认

## 问题现象

在“日常运营中心 → 新增租客账单费用”保存水电费、维修转收费等项目后，系统立即增加租客账单应收，没有经过财务确认。

## 复现与根因

- 复现：新增费用后，费用立即出现在已入账汇总，应收金额同步增加。
- 根因：`AdminPropertyOperationsService.addCharge` 写入 `rent_invoice_items` 后直接调用 `increaseInvoiceAmount`，费用没有对应的待审核财务记录。

## 修复方案

- 新增费用时创建 `finance_records(record_type='tenant_charge', confirmation_status='pending')`，并通过 `rent_invoice_items.finance_record_id` 关联费用明细。
- 待确认费用不增加 `rent_invoices.amount_due`，也不计入租客账单分类汇总。
- 财务确认时原子更新审核状态并增加账单应收；驳回时只更新审核状态，不改变应收。
- 已确认费用退回待确认时同步撤销应收；账单已有收款且无法安全撤销时拒绝退回。
- 历史费用的 `finance_record_id` 保持为空，并按已确认处理，避免改变既有账单。
- 运营中心将“开支确认”升级为“财务确认”，合并展示待确认开支和租客账单费用；财务确认模块新增独立“租客账单”入口。

## 数据库迁移

执行 `database/migrate_tenant_charge_finance_review.sql`，为 `rent_invoice_items` 增加财务记录关联字段、唯一索引和外键。

## 验证结果

- 后端定向测试：28 项通过，覆盖新增待确认、确认入账、驳回不入账及 MyBatis SQL。
- 前端定向测试：6 项通过，覆盖租金/租客账单隔离、待确认不计汇总和财务入口。
- 前端生产构建：通过。
- 页面验证：运营中心显示“财务确认”；财务确认页面显示独立“租客账单（确认后才增加应收）”页签，接口查询正常。
- 完整后端回归共运行 274 项；272 项通过，2 项因仓库缺少既有 `owner-tenancy-agreement-template.docx` 资源失败，与本次改动无关。
- 完整前端静态测试存在多项仓库既有失败（并发 Vite 端口占用及旧契约断言）；本次相关定向测试均通过。
