# 预收租金未按月份拆分 - 修复报告

## BUG描述
- 页面/功能：财务确认 / 租金确认。
- 操作步骤：在某月租金账单中录入覆盖当月及未来月份的租金收款。
- 期望结果：付款完整覆盖的每个月立即生成独立租金收款、交易编号和收据；不足一个月的尾款不生成该月记录；月份到来后不重复生成账单或收款。
- 实际结果：系统只生成一条总额租金收款，再通过预收租金余额抵扣未来账单，财务列表无法按月份核对。

## 复现步骤
1. 建立月租 RM 1,000、租期至少三个月的租约。
2. 在第一个月账单确认 RM 1,500 租金。
3. 旧逻辑只写入一条 RM 1,500 财务记录，并建立 RM 500 预收余额。
4. 复现测试在修复前报错：`Unable to create rent prepayment balance`，证明仍进入旧预收余额路径。

## 根因分析
- 表象：财务确认历史只有一条跨月汇总收款。
- 根因：`confirmRentCollection` 将全部实收金额写入同一个 `finance_records`，只把当月金额关联账单，剩余金额写入 `lease_rent_credits` 后再抵扣未来账单。
- 定位过程：追踪前端租金确认接口至 `AdminTenancyService.confirmRentCollection`，确认记录合并发生在后端写入阶段，不是前端列表展示问题。

## 修复方案
- 修改文件：`backend/src/main/java/com/ccps/backend/service/AdminTenancyService.java`。
- 收到预交租金时，立即建立金额所覆盖的未来月份账单。
- 按月份欠款顺序分配实收金额，每个月分别建立 `finance_records`、`rent_payments`、收据、现金流和审计记录。
- 未来月份只有完全覆盖当月应收时才建立独立租金记录；不足一个月的尾款保留为预收余额，不建立该月租金记录。
- 同一次付款凭证关联到全部按月拆分的记录。
- 新记录不再建立预收余额；旧预收余额数据仍保留兼容处理。
- 月度账单任务继续使用 `INSERT IGNORE`，配合 `(lease_id, billing_month)` 唯一键跳过已经提前生成的月份。

## 单元测试
- `AdminTenancyServiceTest.confirmsAdvanceRentByCreatingOneRentPaymentRecordForEachCoveredMonth`
  - 验证跨两个月的付款生成两条独立财务记录并分别关联对应账单。
  - 验证新流程不再建立 `lease_rent_credits`。
- `AdminTenancyServiceTest.doesNotCreateMonthlyRentPaymentForPartiallyCoveredFutureMonth`
  - 验证未来月份只覆盖一部分时，不建立该月租金记录，尾款保留为预收余额。
- `AdminTenancyMapperSqlTest.monthlyInvoiceGenerationDoesNotDuplicateMonthsCreatedByAdvanceRent`
  - 验证月度账单 SQL 使用 `INSERT IGNORE` 防止重复月份。
- 租金与财务确认相关回归测试：46 项通过。

## 手动验证步骤
1. 打开财务确认中的租金收款页面。
2. 对 2026 年 1 月账单录入可覆盖 1 月和 2 月的金额。
3. 打开租金确认历史，确认出现 2026-01、2026-02 两条独立收款记录，金额分别对应各月租金。
4. 确认两条记录具有不同交易编号和收据编号，并关联同一付款凭证。
5. 到 2026 年 2 月执行月度账单任务，确认不会再新增 2 月账单或收款记录。

## 影响范围
- 直接影响：管理员租金确认、跨月预交租金、租金确认历史、租金收据。
- 间接影响：租金现金流、租客通知、付款凭证关联和月度账单生成。
- 兼容性：历史预收余额仍可按原逻辑处理；新预交款改为按月份即时入账。
