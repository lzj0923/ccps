# 支出记录接口 500 - 修复报告

## BUG描述

- 页面/功能：管理端财务与支出记录
- 操作步骤：登录管理端并打开支出记录，前端请求 `GET /api/admin/expenses`
- 期望结果：返回支出及维修记录列表
- 实际结果：接口返回 HTTP 500

## 复现步骤

1. 启动后端并使用管理员账号登录。
2. 请求 `GET /api/admin/expenses`。
3. 无筛选和带日期筛选均稳定返回 HTTP 500。

## 根因分析

- 表象：Spring MVC 返回 500，前端无法显示支出记录。
- 根因：`OwnerExpenseMaintenanceMapper` 依赖 MyBatis 构造器自动映射 record DTO，但 `findExpenses` 和 `findMaintenance` 新增付款人、银行及付款账号字段后，SELECT 列顺序与 `ExpenseItem`、`MaintenanceItem` 构造器参数顺序不一致。
- 具体结果：MyBatis 将字符串付款字段传给 `Long`、`int`、`boolean` 等参数，反射构造 DTO 时抛出 `ReflectionException` 和 `IllegalArgumentException`。
- 定位过程：在独立 8081 端口重放管理员请求，依次捕获 `findExpenses` 和 `findMaintenance` 结果映射异常；修复第一条查询后，第二条同类问题继续被原始接口复现并定位。

## 修复方案

- 修改文件：`backend/src/main/java/com/ccps/backend/mapper/OwnerExpenseMaintenanceMapper.java`
- 修改内容：调整 `findExpenses` 与 `findMaintenance` 的 SELECT 投影顺序，使其与对应 record DTO 构造器参数完全一致。
- 修改原因：MyBatis 构造器自动映射要求结果列顺序和参数类型可对应。
- 数据与业务逻辑：未修改查询条件、数据库数据或业务规则。

## 单元测试

- 测试文件：`backend/src/test/java/com/ccps/backend/mapper/OwnerExpenseMaintenanceMapperSqlTest.java`
- 测试用例：
  - `expenseProjectionMatchesExpenseItemConstructorOrder`
  - `maintenanceProjectionMatchesMaintenanceItemConstructorOrder`
- 修复前：两处测试分别稳定检出付款字段位于 DTO 构造参数之前。
- 修复后：Mapper 与服务层定向测试共 5 项全部通过。
- 完整套件：运行 370 项；本次新增测试通过，另有 3 项失败和 4 项错误属于工作区既有问题，与本次修改无关。

## 手动验证步骤

1. 重启当前 8080 后端进程，使 JVM 加载最新 Mapper 注解。
2. 登录管理端并打开支出记录页面。
3. 确认列表能显示支出与维修记录。
4. 切换日期筛选并确认接口仍正常返回。

## 影响范围

- 直接影响：管理端和业主端复用的支出、维修汇总查询。
- 间接影响：新增付款人、银行及付款账号字段的结果映射稳定性。
- 接口验证：无筛选及 2026-08 日期筛选均返回 HTTP 200；测试数据返回 8 条支出和 2 条维修记录。
