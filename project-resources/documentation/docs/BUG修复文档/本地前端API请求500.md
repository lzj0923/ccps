# 本地前端 API 请求 500 - 修复报告

## BUG描述
- 页面/功能：本地 Vue 前端 API 请求
- 操作步骤：登录本地前端后访问依赖后端接口的页面
- 期望结果：前端通过 Vite 代理访问本机后端
- 实际结果：API 请求返回 HTTP 500

## 复现步骤
1. 保持后端运行在 `127.0.0.1:8080`。
2. 启动前端开发服务器。
3. 通过前端开发服务器请求 `/api/webhooks/whatsapp`。
4. 请求返回 HTTP 500。

## 根因分析
- 表象：本地前端登录后接口返回 500。
- 根因：`frontend/.env.local` 的 `VITE_DEV_PROXY_TARGET` 仍指向已失效的旧 Cloudflare Quick Tunnel 域名。
- 定位过程：确认后端接口本地返回 200，前端静态页面返回 200，但同一接口经 Vite 代理返回 500。

## 修复方案
- 修改文件：`frontend/.env.local`
- 修改内容：将开发代理目标改为 `http://127.0.0.1:8080`。
- 修改原因：本地开发应直接访问本机后端，避免依赖临时且会变化的 Quick Tunnel 域名。

## 单元测试
- 配置类问题采用开发服务器集成验证。
- 临时启动 Vite 于 `localhost:5174`。
- 首页返回 HTTP 200。
- 经 Vite 代理调用 Webhook 验证接口返回 HTTP 200 和正文 `12345`。

## 手动验证步骤
1. 停止原前端进程。
2. 重新运行 `npm run dev`。
3. 刷新浏览器并重新登录。
4. 确认相关 API 不再返回 500。

## 影响范围
- 直接影响：本地开发环境的所有 `/api` 请求。
- 间接影响：无；生产环境配置未修改。
- 回归测试结果：通过。
