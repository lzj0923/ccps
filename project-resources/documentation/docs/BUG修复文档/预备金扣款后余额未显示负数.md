# 预备金扣款后余额未显示负数 - 修复报告

## BUG描述
- 页面/功能：管理端「预备金」及「收支与维修」预备金扣款。
- 操作步骤：在余额不足时建立一笔由预备金支付的支出。
- 期望结果：支出照常扣除，预备金余额显示为负数，并记录业主后续应补金额。
- 实际结果：财务记录显示已支付，但预备金余额仍为 RM 0.00，且没有扣款流水。

## 复现步骤
1. 选择当前余额为 RM 0.00 的预备金账户。
2. 建立 RM 1,000.00 的预备金扣款支出。
3. 查询财务记录、现金流记录、预备金账户及预备金流水。
4. 复现结果：财务记录为已支付/已确认，现金流未关联预备金账户，账户余额未变化，扣款流水缺失。

## 根因分析
- 表象：预备金页面显示的余额没有变成负数。
- 根因：当前数据库仍运行旧版预备金触发器。旧触发器在余额不足时取消预备金关联和扣款，但财务记录仍保留「预备金已支付」状态，造成账务状态不一致。
- 定位过程：先确认前端金额格式化会保留负号，再对照账户、财务记录、现金流、扣款流水和数据库触发器，定位到运行中的触发器仍包含余额充足限制。

## 修复方案
- 修改文件：`database/migrate_reserve_expense_policy.sql`
- 修改内容：
  - 明确选择预备金支付时，不再要求余额必须充足，允许扣款后形成负数。
  - 历史补账程序识别 `payment_method = 'reserve_account'` 的漏扣记录，即使余额不足也补扣并生成流水。
  - 保留非明确预备金支付记录的保守自动分配规则，避免误扣。
- 数据修复：已重新应用迁移，将漏扣的 RM 1,000.00 补记到账户及流水，账户余额修正为 RM -1,000.00。

## 单元测试

- 测试结果：专项测试及相关预备金、支出服务测试通过。

## 手动验证步骤
1. 刷新管理端「预备金」页面。
2. 查看对应账户，确认当前余额为 RM -1,000.00。
3. 查看账户流水，确认存在 RM 1,000.00 的预备金扣款。
4. 后续可用余额不足的账户再建立一笔预备金支出，确认余额继续向负数变化。

## 影响范围
- 直接影响：预备金扣款、余额显示、扣款流水及历史漏扣补账。
- 间接影响：收支与维修中选择预备金支付的支出记录。
- 回归测试结果：通过；未启动后端服务。
