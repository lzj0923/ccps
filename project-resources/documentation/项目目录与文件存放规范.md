# CCPS 项目目录与文件存放规范

## 1. 目的

本规范用于统一 CCPS 项目的源码、配置、文档、交付物和生成文件位置。任何人工操作、脚本、测试或自动化工具在新建文件前，都必须先确定文件所属类别，不得把临时文件、日志、截图、压缩包或说明文档散落在项目根目录及源码目录。

## 2. 总体原则

1. 项目根目录只保留系统运行、构建、部署和协作必需的目录与配置文件。
2. 业务源码只放在 `backend/`、`frontend/` 对应源码目录中。
3. 数据库正式结构和可重复执行的迁移脚本只放在 `database/`。
4. 非运行文档、交付物、部署快照和生成物统一放在 `project-resources/`。
5. 可重新生成的文件不得提交到源码目录，也不得作为正式业务资源使用。
6. 修改现有文件时保留原路径；只有确认分类错误时才进行迁移，并同步修正引用。

## 3. 项目根目录

| 路径 | 用途 | 可以放置 | 禁止放置 |
| --- | --- | --- | --- |
| `.agents/` | 项目级智能代理技能和工作流 | `SKILL.md`、技能脚本、技能参考资料 | 业务源码、普通文档、截图和输出文件 |
| `.codex/` | Codex 项目配置和任务记录 | Codex 配置、任务日志 | 产品文档、构建产物、业务附件 |
| `.vscode/` | VS Code 工作区设置 | 编辑器共享配置 | 个人临时文件、编译结果 |
| `backend/` | Spring Boot 后端工程 | Java 源码、资源、测试、Maven 配置 | 演示截图、部署压缩包、手工日志 |
| `frontend/` | Vue 3 前端和移动端工程 | Vue/JS/CSS 源码、测试、Vite/Capacitor 配置 | 项目说明文档、数据库快照、手工输出 |
| `database/` | 数据库正式结构与演进脚本 | Schema、migration、seed、backfill、verify 脚本 | 数据库导出快照、临时 SQL、运行日志 |
| `docker/` | 容器镜像及初始化配置 | Dockerfile、Nginx、MySQL 初始化文件 | 本地数据库数据、镜像导出包 |
| `scripts/` | 可复用的部署、迁移和验证脚本 | `.sh`、`.ps1`、`.cmd`、`.py`、`.mjs` | 一次性输出、执行日志、截图 |
| `tools/` | 项目维护工具 | 可复用工具脚本及说明 | 产品源码、交付成品 |
| `project-resources/` | 非运行辅助资料统一入口 | 文档、交付物、部署快照和生成文件 | 系统运行时必须加载的资源 |

根目录允许保留的文件：

| 文件 | 用途 |
| --- | --- |
| `README.md` | 项目入口、启动方式和结构摘要 |
| `AGENTS.md` | 项目协作及文件落位规则 |
| `.gitignore` | Git 忽略规则 |
| `docker-compose.yml` | 本地容器编排 |
| `package.json`、`package-lock.json` | 根工程 Node 配置 |
| `skills-lock.json` | 项目技能依赖锁定 |
| `tokens.css` | 前端运行时直接引用的全局设计令牌 |

除构建工具明确要求的配置文件外，不得再向根目录增加 Word、Excel、PDF、图片、SQL 快照、压缩包、日志或临时脚本。

## 4. 后端目录 `backend/`

| 路径 | 用途 | 文件规则 |
| --- | --- | --- |
| `src/main/java/` | 后端业务源码 | 按 `controller`、`service`、`mapper`、`dto`、`config` 等包组织 |
| `src/main/resources/` | 后端运行资源 | `application.yml`、启动 Schema、静态页面、系统实际使用的合同模板和图片 |
| `src/test/java/` | 后端自动化测试 | 测试源码；测试生成样本必须输出到 `project-resources/generated/tmp/` |
| `pom.xml` | Maven 工程配置 | 仅维护依赖、插件和构建配置 |
| `config/` | 本地或部署配置 | 敏感配置不得提交；正式环境优先使用环境变量 |
| `uploads/` | 本地运行上传内容 | 仅运行时数据，禁止当成源码或模板 |
| `backups/` | 系统备份功能生成的数据 | 仅备份文件，禁止手工文档混入 |
| `target/` | Maven 编译输出 | 自动生成，不手工修改、不提交 |
| `tmp/` | 后端运行时短期临时数据 | 仅程序确实需要时使用；人工生成样本不得放这里 |

后端启动或调试日志统一写入 `project-resources/generated/logs/backend/`，不得写在 `backend/` 根目录。

## 5. 前端目录 `frontend/`

| 路径 | 用途 | 文件规则 |
| --- | --- | --- |
| `src/components/` | 可复用界面组件 | 一个组件负责一个清晰界面职责 |
| `src/pages/` | 页面级组合与路由页面 | 不堆放通用工具或数据访问代码 |
| `src/composables/` | Vue 状态和交互逻辑 | 可复用的组合式逻辑 |
| `src/services/` | API 与外部服务访问 | 统一封装请求，不在组件内散写重复接口逻辑 |
| `src/data/` | 静态配置及展示数据 | 不存放运行时用户数据 |
| `src/i18n/` | 多语言文本 | 简体、繁体、英文资源及生成后的语言文件 |
| `src/systems/` | 按业务端或子系统划分的界面 | 例如业主端系统 |
| `src/utils/` | 无界面通用工具 | 日期、导出、格式化等纯工具 |
| `test/`、`tests/` | 前端自动化测试 | 测试代码；截图和报告输出到 `project-resources/generated/` |
| `scripts/` | 前端专用维护脚本 | 仅限前端构建、国际化和移动端相关脚本 |
| `android/`、`ios/` | Capacitor 原生工程 | 移动端工程配置和源码 |
| `dist/` | Vite 生产构建结果 | 自动生成，不手工修改、不提交 |
| `node_modules/`、`.vite/` | 依赖及构建缓存 | 自动生成，不提交 |

前端启动或调试日志统一写入 `project-resources/generated/logs/frontend/`，不得写在 `frontend/` 根目录。

## 6. 数据库目录 `database/`

| 文件类型 | 命名和用途 |
| --- | --- |
| `schema.sql` | 当前完整数据库结构基线 |
| `migrate_*.sql` | 正式增量迁移；名称描述具体业务变更 |
| `backfill_*.sql` | 对既有数据进行一次性补全，但脚本必须可审查 |
| `seed_*.sql` | 开发或测试初始化数据 |
| `verify_*.sql` | 数据结构或业务规则验证脚本 |
| `recalculate_*.sql`、`repair_*.sql` | 明确目的的数据修复脚本 |
| `DATABASE_DESIGN.md` | 数据库结构和关系说明 |

数据库完整导出、服务器下载的 SQL 和部署时合并产生的 SQL 不属于迁移源码，必须放到 `project-resources/deployment/database-snapshots/`。

## 7. 部署与工具目录

### `docker/`

- `backend/`：后端镜像构建文件。
- `frontend/`：前端镜像和 Nginx 配置。
- `mysql/`：MySQL 初始化资源。
- 不得保存容器日志、数据库数据目录或导出的镜像包。

### `scripts/`

- 保存需要重复使用的部署、重启、迁移和验证脚本。
- 脚本产生的日志、截图、JSON、PDF 或压缩包必须显式输出到 `project-resources/generated/` 或 `project-resources/deployment/`。
- 一次性试验脚本放入 `project-resources/generated/tmp/`，确认长期复用后再移入 `scripts/`。

### `tools/`

- 保存跨模块使用的项目维护工具。
- 工具本身放这里，工具生成的结果不得放这里。

## 8. 辅助资料目录 `project-resources/`

### `documentation/`

| 路径 | 用途 |
| --- | --- |
| `documentation/docs/` | 正式需求、设计、问题记录、配置说明和操作手册源文件 |
| `documentation/docs/adr/` | 架构决策记录 |
| `documentation/docs/BUG修复文档/` | 已完成问题的修复报告 |
| `documentation/docs/reports/` | 阶段性报告 |
| `documentation/docs/screenshots/` | 文档实际引用且需要长期保存的截图 |
| `documentation/docs/superpowers/` | 历史设计规格和实施计划 |
| `documentation/project-plans/` | 项目进度和后续工作计划成品 |
| `documentation/CONTEXT.md` | 领域术语和长期上下文 |
| `documentation/design.md` | 项目视觉或设计约定 |

普通调试截图不得放入 `documentation/docs/screenshots/`，只有被正式文档引用且需要长期保存的截图才可以进入该目录。

### `deliverables/`

- 保存已经确认、需要交给客户或安装使用的最终成品。
- 包括正式用户手册、最终 APK、正式演示文稿或签收文件。
- 中间预览、草稿、检查报告和重复版本不得放在这里，应放入 `generated/`。

### `deployment/`

| 路径 | 用途 |
| --- | --- |
| `deployment/packages/` | 前端部署包、数据库迁移包等可发布压缩包 |
| `deployment/database-snapshots/` | 数据库完整导出、同步副本和历史部署 SQL |

正式数据库迁移仍必须保存在根目录 `database/`，不能只存在于部署快照中。

### `generated/`

| 路径 | 用途 |
| --- | --- |
| `generated/downloads/` | 工具下载缓存、SDK 或临时下载内容 |
| `generated/output/` | 历史 PDF 等单次生成结果；现有兼容目录 |
| `generated/outputs/` | 历史演示文稿和批量生成结果；现有兼容目录 |
| `generated/tmp/` | 临时构建副本、测试渲染、预览图片和一次性脚本 |
| `generated/logs/backend/` | 后端本地启动和调试日志 |
| `generated/logs/frontend/` | 前端本地启动和调试日志 |

`generated/` 中的内容默认不进入 Git。任何系统运行时必须使用的模板、图片或配置都不能只保存在这里。

## 9. 隐藏目录和自动生成目录

| 路径 | 用途与规则 |
| --- | --- |
| `.git/` | Git 内部数据，禁止人工修改 |
| `.gradle-cache/` | Android/Gradle 缓存，可重新生成，不提交 |
| `.pnpm-store/` | 包管理器缓存，可重新生成，不提交 |
| `.vite/` | Vite 缓存，可重新生成，不提交 |
| `.tmp/` | 工具临时缓存，可重新生成，不存放唯一资料 |
| `.hallmark/` | 设计工具工作数据，不作为系统运行资源 |
| `.codex-video-review/`、`.codex-video-tools/` | 视频工具缓存和工作文件，不作为源码 |

## 10. 文件落位速查表

| 新文件类型 | 正确位置 |
| --- | --- |
| Java 后端源码 | `backend/src/main/java/` 对应包 |
| 后端测试 | `backend/src/test/java/` |
| Vue/JS/CSS 前端源码 | `frontend/src/` 对应目录 |
| 前端测试 | `frontend/test/` 或 `frontend/tests/` |
| 数据库迁移 | `database/migrate_*.sql` |
| 数据库导出快照 | `project-resources/deployment/database-snapshots/` |
| 部署压缩包 | `project-resources/deployment/packages/` |
| 需求、设计和配置说明 | `project-resources/documentation/docs/` |
| Bug 修复报告 | `project-resources/documentation/docs/BUG修复文档/` |
| 正式交付文件 | `project-resources/deliverables/` |
| 临时截图、PDF 渲染和测试样本 | `project-resources/generated/tmp/` |
| 后端日志 | `project-resources/generated/logs/backend/` |
| 前端日志 | `project-resources/generated/logs/frontend/` |
| 演示文稿生成结果 | `project-resources/generated/outputs/`；确认最终版后复制到 `deliverables/` |

## 11. 创建文件前的检查顺序

1. 判断该文件是否是系统运行或构建必需文件。
2. 如果是源码，放入对应模块的源码或测试目录。
3. 如果是数据库结构变更，放入 `database/` 并使用明确前缀命名。
4. 如果是说明文档或交付物，放入 `project-resources/` 对应分类。
5. 如果文件可以重新生成，必须放入 `project-resources/generated/`。
6. 创建后检查项目根目录和 `backend/`、`frontend/` 根目录，确认没有新增散落日志、截图、压缩包或临时文件。

## 12. 明确禁止事项

- 禁止在项目根目录生成 `tmp/`、`output/`、`outputs/`、`downloads/` 或新的散落文档。
- 禁止在 `backend/`、`frontend/` 根目录保存启动日志。
- 禁止把数据库导出文件当作 migration 放入 `database/`。
- 禁止把测试生成的图片、PDF、Word 或 JSON 放入源码和测试目录。
- 禁止把唯一原件只保存在被 Git 忽略的缓存目录。
- 禁止为了方便复制整个源码树到项目根目录或辅助文档目录。
