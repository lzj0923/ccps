# R02／R07／R09 需求基線與欄位矩陣

版本：0.1（第一步草案）  
日期：2026-07-20  
狀態：R02 第一個垂直切片已落地；R07／R09 及 R02 接管附件仍待後續確認

## 1. 使用方式

這份文件先固定三個模組的業務邊界、名詞、狀態和角色，再進入資料表及頁面開發。帶有「待確認」的項目不是已決定的需求，必須在 EIP 明細頁或現場流程確認後才能進入開發。

本文件採用以下原則：

- 按業務閉環定義需求，不按選單頁面拆功能。
- 「租管委託」、「租約」、「收支台帳項目」和「下架案件」是四個不同概念，不能用一個 status 欄位代替。
- 財務資料不可直接刪除；更正使用調整或沖銷。
- 暫停營運不等於處置持有關係；只有真正結束持有關係才進入 Disposed Holding。

## 2. 模組邊界

| 模組 | 本階段納入 | 本階段不納入 | 主要產出 |
| --- | --- | --- | --- |
| R02 租管物件管理 | 租管委託、物件接管、物件資料、負責人、狀態歷史、附件、租管服務設定 | 行銷投放、帶看 CRM、完整租約會計結算 | 可營運的 Rental Mandate 及 Property Handover |
| R07 收支紀錄管理 | 收入／支出、科目、收付款對象、憑證、審核、付款、調整／沖銷、對帳、匯出 | 完整總帳、薪資、稅務申報 | 可追溯的 Cashflow Entry |
| R09 下架物件管理 | 下架申請、依賴檢查、審核、結算、通知、暫停／恢復、永久封存 | 直接刪除房產、繞過未結算資料強制下架 | 可審計的 Offboarding Case |

## 3. 名詞基線

| 名詞 | 本專案定義 | 不應混用 |
| --- | --- | --- |
| Rental Service | Operating Holding 上的出租服務開關 | 不是租約，也不是出租狀態 |
| Rental Mandate | 業主委託 CCPS 租管某個持有物件的期間性案件 | 不是 Rental Service flag |
| Lease | 租客與單位之間的期間性租約 | 不是租管委託 |
| Cashflow Entry | 一筆可審計的收入／支出台帳項目 | 不是單純付款畫面 |
| Finance Review | 財務記錄的審核／批准／拒絕／作廢決定 | 不是一般通知 |
| Offboarding Case | 暫停或結束營運服務的案件 | 不是刪除物件 |
| Disposed Holding | 持有關係已永久結束的歷史狀態 | 不是暫停出租 |

## 4. 狀態基線

### 4.1 R02：Rental Mandate

建議狀態：`draft → pending_review → active → suspended → terminated`。

| 狀態 | 進入條件 | 可做操作 | 離開條件 |
| --- | --- | --- | --- |
| draft | 建立委託資料尚未送審 | 編輯、補附件、刪除草稿 | 送出審核 |
| pending_review | 委託資料及必要附件齊全 | 審核、退回補件 | 核准或退回 |
| active | 業主授權、物件接管及負責人已確認 | 出租、維修、收支、提醒 | 暫停或終止 |
| suspended | 暫停出租或暫停營運，但持有關係仍有效 | 結算既有事項、恢復 | 恢復或終止 |
| terminated | 委託已結束且完成交接 | 查詢歷史、下載文件 | 不可直接恢復；新委託另建 |

### 4.2 R07：Cashflow Entry

建議狀態：`draft → pending_review → approved → paid → posted → voided`。現有租金確認流程可保留自己的 receipt status，但最後必須映射到台帳狀態。

| 狀態 | 意義 | 必要資料 |
| --- | --- | --- |
| draft | 尚未提交的收支草稿 | 方向、金額、日期、科目、對象 |
| pending_review | 等待財務審核 | 憑證、申請人、提交時間 |
| approved | 已批准可付款／入帳 | 審核人、審核時間、理由 |
| paid | 已發生付款或收款 | 付款日、付款方式、銀行參考 |
| posted | 已正式入帳並可供報表／同步 | 科目映射、幣別、匯率、同步狀態 |
| voided | 已作廢，原記錄仍保留 | 作廢人、作廢時間、原因、沖銷關聯 |

### 4.3 R09：Offboarding Case

建議狀態：`draft → pending_review → settlement → closed`；暫停類案件可由 `closed` 進入 `restored`，永久處置不可恢復。

| 狀態 | 進入條件 | 阻擋條件 |
| --- | --- | --- |
| draft | 提出下架原因及生效日 | 缺少申請人或原因 |
| pending_review | 下架資料及附件齊全 | 有效租約、欠款、未完成維修或未審核收支 |
| settlement | 審核通過，開始結算 | 押金、預備金、租金或水電未結算 |
| closed | 結算、交接、通知及封存完成 | 任一結算項目未完成 |
| restored | 暫停案件重新營運 | 只允許暫停類案件，不適用 Disposed Holding |

## 7. 第一階段驗收條件

- 業務人員可以建立一筆 Rental Mandate，指定物件、業主、負責人、期間和服務類型。
- Rental Mandate 未核准前，不可產生正式出租營運任務。
- 每一筆 Cashflow Entry 都能回答「哪個物件、哪個對象、收入還是支出、金額多少、誰審核、是否付款、是否同步」。
- 作廢和更正不會刪除原始財務記錄。
- 新增 Offboarding Case 時，系統可以列出未結租約、欠款、押金、預備金、維修、未審核收支及未同步批次。
- 暫停營運可以恢復；Disposed Holding 不可被當作一般下架恢復。
- R02、R07、R09 的新增、審核、付款、下架和恢復都保留操作人、時間、原因和附件。

## 8. 待業務確認問題

1. EIP R02 的「租管物件」是否包含委託合約、管理費、佣金、家具清單、鑰匙與點交？哪些欄位必須一比一保留？
2. EIP R07 是否允許手動新增收入？收支是否需要多幣別、稅額、發票及銀行對帳？
3. EIP R09 的「下架」是暫停出租、終止租管、業主收回，還是包含出售／處置？各類型是否允許恢復？
4. 哪些角色可以建立、審核、付款、作廢和恢復？同一人是否禁止同時申請和審核？
5. SQL Account 的科目、稅碼、幣別和外部回執格式由誰提供？
6. 下架時押金、預備金、未收租金和未付費用的結算責任人是誰？

## 9. 已落地的 R02 第一個垂直切片

已完成 `Rental Mandate 建立 → 提交審核 → 核准啟用 → 暫停／恢復／終止 → 狀態歷史`。後端接口位於 `/api/admin/rental-mandates`，資料表及既有資料庫升級腳本分別在 `database/schema.sql` 與 `database/migrate_rental_mandates.sql`。核准時會同步啟用 `owner_unit_services.RENTAL`，所有狀態轉換寫入歷史及 `audit_logs`。

接著已補上 `Property Handover`：可在啟用／暫停委託下保存交接日期、屋況摘要、鑰匙、門卡、水電錶、設備清單、交接人及備註，並可由草稿標記為完成；接口為 `/api/admin/rental-mandates/{mandateId}/handover`，升級腳本為 `database/migrate_property_handovers.sql`。業主端只保留出租意向／服務開關；正式委託及文件由管理端建立和審核。

文件留存也已接入既有 `documents`／`document_links`：委託書、授權文件、交接照片和設備清單可上傳、列表查看及下載；接口為 `/api/admin/rental-mandates/{mandateId}/documents`。建立委託候選單位現在只包含已啟用出租服務且沒有未終結委託的單位；租約建立接口也強制要求該單位存在有效 `active` 委託。
