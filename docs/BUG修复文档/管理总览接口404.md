# 管理总览接口 404 - 修复报告

## BUG描述

- 页面/功能：后台管理总览
- 操作步骤：管理员登录后打开 `/admin/dashboard`
- 期望结果：显示单位、入住率、租金、押金及区域统计
- 实际结果：页面显示“管理总览加载失败，服务请求失败（HTTP 404）”

## 复现步骤

1. 调用 `POST /api/auth/admin/login` 建立管理员会话。
2. 携带会话 Cookie 调用 `GET /api/admin/dashboard`。
3. 线上旧后端连续三次稳定返回 HTTP 404。

## 根因分析

- 表象：管理总览 API 返回 404。
- 根因：线上前端已经调用新接口，但运行中的后端 JAR 及服务器源码均缺少 `AdminDashboardController`、`AdminDashboardService` 和 `AdminDashboardResponse`，属于前后端部署制品版本不一致。
- 定位过程：绕过反向代理直连 `127.0.0.1:8082` 仍复现；检查线上 JAR 内容确认缺少管理总览相关类；本地当前源码及构建产物包含完整接口。

## 修复方案

- 使用当前本地源码重新构建后端 JAR。
- 将旧线上 JAR 备份为 `/root/ccps-backend-before-dashboard-fix.jar`。
- 重新构建 `ccps-backend` 镜像并替换容器，使前后端接口版本一致。

## 单元测试

- 测试文件：`backend/src/test/java/com/ccps/backend/controller/AdminDashboardControllerTest.java`
- 测试用例：`exposesManagementDashboardAtExpectedApiRoute`
- 目标测试结果：1 项通过，0 项失败。
- 完整套件结果：177 项中 174 项通过；另有 1 项既有电子签署 SQL 断言失败、2 项既有 Word 模板资源缺失错误，均与本次接口 404 无关。

## 手动验证步骤

1. 以管理员身份登录。
2. 打开“管理总览”。
3. 确认页面显示统计卡片和区域经营数据，不再出现 HTTP 404。
4. 点击“刷新数据”，确认页面可再次正常加载。

## 影响范围

- 直接影响：后台管理总览接口及页面。
- 间接影响：后端容器使用当前本地完整构建版本。
- 线上验证：登录接口 HTTP 200；管理总览接口 HTTP 200，并返回完整统计 JSON。
